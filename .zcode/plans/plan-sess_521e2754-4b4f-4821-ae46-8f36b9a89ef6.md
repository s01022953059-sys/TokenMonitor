## 修复 Windows 端 MiniMax Code 未统计 (v1.5.13)

### 背景
v1.5.11 / v1.5.12 在 macOS 端 (`scanner.py`) 修复了:
- **v1.5.11** MiniMax Code 数据源升级 SQLite 主源 + JSONL 兜底 + turn_id 去重 (mvs_ 前缀过滤)
- **v1.5.12** `normalize_model_name` 剥 `custom_provider:` / `custom-local:` 前缀

但 Windows 端是 Go 单体 (`go_build/main.go`),有**独立的 `scanMiniMaxTokens` 和 `normalizeModelName`**。**完全没同步这两个修复**:
- `grep custom_provider go_build/*.go` → 0 命中
- `grep mvs_ go_build/*.go` → 0 命中
- `grep local_runtime_token_usage go_build/*.go` → 0 命中

→ Windows 用户在 `~/.minimax/v2/sqlite/runtime-state.sqlite` 的真实数据**完全没被读到**,模型名**还是带 `custom_provider:` 前缀**。

### 改动 (5 个文件)

**1. `go_build/main.go`** — 唯一 Go 逻辑改动 (~250 行)

a. **L306-345 `normalizeModelName`**:在 `aliases` 表之前加 2 条规则剥前缀
```go
// v1.5.13 同步: 跟 Python scanner.py normalize_model_name 保持一致
if strings.HasPrefix(s, "custom_provider:") {
    rest := s[len("custom_provider:"):]
    if idx := strings.Index(rest, "/"); idx >= 0 {
        s = rest[idx+1:]
    } else {
        s = rest
    }
} else if strings.HasPrefix(s, "custom-local:") {
    s = s[len("custom-local:"):]
}
```

b. **L92-103 `LogEntry` struct**:加 `TurnID string \`json:"turn_id,omitempty"\``(跨源去重要靠它)

c. **L280-282 加常量 + L947-1060 重写 `scanMiniMaxTokens`**:拆成 `scanMiniMaxSQLite` (主) + `scanMiniMaxJSONL` (兜底) + `mergeMiniMaxSources` (turn_id 去重),对齐 `scanner.py` v1.5.11 行为
   - SQLite 路径复用 `sql.Open("sqlite", ...)` + busy_timeout (跟 `scanZCodeTokens` L859 同模式)
   - 列: `session_id, turn_id, model, ts, input_tokens, output_tokens, reasoning_tokens, cache_read_tokens, cache_write_tokens`
   - 过滤 `session_id LIKE 'mvs_%'` (前 N 个字符匹配,避免 LIKE 参数化踩坑)
   - `ts` 是毫秒, `ts/1000` 转秒
   - `total = input + output`,reasoning 不计入 (跟 macOS v1.5.11 一致)
   - `i_cached = cache_read + cache_write`
   - 库不存在 / 表缺失 / 列缺失 / 库打开失败都静默返回 (跟 ZCode 同模式)
   - JSONL 路径保留原 L947-1060 逻辑但加 `TurnID` 字段 (空)
   - `mergeMiniMaxSources` 按 turn_id (有) / (session_id, timestamp) (无) 去重,SQLite 永远赢

d. **L1060 之后现有调用点** (`L1301` / `L1956` / `L2931` 等) 一行不动, 函数签名不变

**2. `go_build/minimax_sqlite_test.go` (新)** — Go 测试 (沿用 `scanner_accuracy_test.go` 风格)
- `TestScanMiniMaxSQLite*` 系列: ms→s / total=in+out / reasoning 不计 / cache 拆分 / mvs_ 前缀过滤 / 时间窗过滤 / 库缺失 / 表缺失 / 零 total 跳过
- `TestMergeMiniMaxSourcesDedupesByTurnID` / `TestMergeMiniMaxSourcesFallsBackToSessionTS`
- `TestScanMiniMaxJSONLCompatibility` (旧 v1 路径回归)
- `TestNormalizeModelNameStripsCustomProviderPrefix` 表驱动:custom_provider / custom-local / 大小写 / 无前缀 / 空 None

- 不动 `_dedupEvents` / 其它 scanner
- 不动 `community.go` / Windows GUI / 系统托盘

### 验证
- `cd go_build && go test ./...` 全绿
- `bash verify_release.sh` PASS

### 风险
- 极低: 复用现有 `sql.Open` + busy_timeout 模式 (ZCode / Hermes / Codex 已经在用)
- 兼容: 旧 JSONL 路径保留, 只增量不替换
- 去重: turn_id 是稳定 UUID, 跨源不会误合并
