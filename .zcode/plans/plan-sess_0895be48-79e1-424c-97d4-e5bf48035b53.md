# 方案：排名趋势数据完整性修复（零值不断线 + 今日实时数据补全）

## 三个问题根因

**问题 1 — 缺数据用虚线**：后端 `_build_rank_history_series` 第 626 行对没数据的天已经返回 `tokens=0`（不是 null）。但前端把 0 转 null → `spanGaps:false` 断开 → gapBridge 画虚线。鹏帅要求：**没数据默认用 0，画实线不断开**（0 也是有效值，不要虚线）。

**问题 2 — 小昆数据完全没有**：series 选取按区间累计 token 降序取 top10（第 613-616 行）。小昆若累计排不进前 10 就不出现——这是预期行为。但如果小昆有数据却没出现，说明归档里压根没有他。需确认归档 participants 是否包含全量用户（v1.4.63 已补全零用量排名，理论上应有）。本方案不改变 top10 选取逻辑，但通过问题 3 的"今日实时补全"让今天的数据更完整。

**问题 3 — 今天没汇总取实时数据**：归档每天 23:55 生成，今天的归档还没有 → 今天的数据点缺失。`get_community_stats` 返回的 `leaderboard`（`id/display_name/tokens`）结构与归档 participants 兼容，可直接当今天的 snapshot 拼到序列末尾。

## 修复 A：前端——零值不断开（问题 1）

`renderRankHistory` 里 `tokenData` 的映射改回保留 0（不转 null）：

```js
// 改前：0 → null 导致断开 + 虚线
const tokenData = tokenValues.map(v => (Number(v) > 0 ? Number(v) : null));

// 改后：0 保留为 0（对数轴 min:100 下 0 会被画在底部，但不断开）
const tokenData = tokenValues.map(v => Number(v) || 0);
```

但 Chart.js 对数轴对 0 无定义会报错/不画。解决：**把 y 轴 min 从 100 降到 1**，0 值点画在 y=1 的位置（底部），折线连续。同时 `spanGaps` 改回 `true`（不再断开）。

gapBridge 插件：0 值不再是 null，不会触发虚线，插件自然不画——可以保留插件代码（无副作用），也可以移除。**保留**（未来若真有 null 仍兜底）。

末端标签：`tokens <= 0` 的过滤改为 `tokens < 0`（0 值用户仍画标签）。

## 修复 B：后端——今日实时数据补全（问题 3）

在 `get_community_history` 末尾（构建 result 之后），调用 `get_community_stats` 取今日实时 leaderboard，转成 snapshot 拼到序列末尾：

```python
# 若今天尚无归档（归档 23:55 才生成），用实时排行榜补一个今天的 snapshot
today_str = <北京时间今日>
existing_dates = set(result["dates"])
if today_str not in existing_dates:
    stats = get_community_stats(force_refresh=False)
    today_leaderboard = stats.get("leaderboard") or []
    if today_leaderboard:
        today_snapshot = {
            "date": today_str,
            "participants": [{"id": m["id"], "display_name": m["display_name"], "tokens": m["tokens"]} for m in today_leaderboard],
        }
        snapshots.append(today_snapshot)
        snapshots.sort(key=lambda s: s.get("date", ""))
        result = _build_rank_history_series(snapshots)
        result.update({...原有字段...})
```

注意：只补"今天"，不重复补已有归档的日期。`get_community_stats` 已有缓存，不会重复请求。

## 修复 C：Go 端对齐（AGENTS.md 硬约束）

`go_build/community.go` 的 `buildCommunityRankSeries` 和 history handler 要同步：今日实时数据补全逻辑。Go 端的 `getCommunityStats` 同样返回 leaderboard，结构兼容。
