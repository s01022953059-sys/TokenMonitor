# 安全与执行边界

补充 GOV-01、GOV-06 至 GOV-09，覆盖误操作、提示注入、越权、上下文污染、重复执行、供应链变化与数据外流。控制由执行环境落实，Markdown 与格式检查不能替代它们。

## 可信授权与门禁

按任务赋予分析、修改、验证与发布权限，不要求为简单任务固定增加多个 Agent。高影响动作在工具入口独立核实身份、目标、参数、有效期与撤销状态。使用原生受保护分支、可信 CI 与审阅权限隔离；不能允许 Agent 同时改批准记录、门禁和保护设置后自行放行。规则与门禁代码变更也需审阅。

授权与验收分别判断；用户确认界面正常不自动授权发布，授权发布也不证明测试通过。批准绑定实际动作与产物；结果未知先查询并使用幂等记录。

## 凭据与数据

客户端、源码与公开模板不得内置团队通用长期推送凭据或解密秘密。按平台使用系统凭据库/秘密管理服务，最小权限、短期授权、撤销与轮换。加密正确不证明数据安全，还要验证密钥分发、访问、备份与删除。

提交前检查暂存内容及必要历史范围，结合数据分类审查；扫描器不能识别全部秘密。若确认有效凭据曾公开，先撤销/轮换再处理历史，只删当前文件不足。本次规则迁移未审计或重写历史，也未核实历史业务系统的实际凭据状态。

项目列出数据来源、分类、接收模型/工具/服务、存储、保留、访问和删除方法。日志最小化脱敏，上报范围由用户或组织策略授权，不因界面简洁而隐藏数据流。示例使用合成数据，经验不携带历史用户命令或私有业务快照。

## 测试隔离与更新

移除调试按钮不能证明 API 安全。生产默认关闭 Mock 路由，测试使用独立环境和数据；诊断接口服务端鉴权、资源范围校验与审计。按适用场景检查跨站请求、Origin 与会话边界，localhost 不免除威胁分析。回归覆盖匿名、越权和生产测试路由拒绝。

固定规则、依赖与工具版本，升级审阅差异，必要时校验签名与可信摘要。更新器验证发布者/制品，限制来源，保留旧版本并验证失败恢复；迁移先确认备份与兼容。工作流须在托管平台启用，配置文件存在不代表分支已受保护。

## 审计与处置

记录 task_id、actor、工具/目标、参数摘要、规则版本、授权来源、时间及结果；敏感参数脱敏，不记录隐藏思考过程或秘密明文。证据由受控系统保存，禁止 Agent 抹除失败。异常时停止受影响写入、保全证据、核实波及范围与恢复路径，不自动扩大操作范围。
