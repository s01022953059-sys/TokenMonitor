# 蓝方治理改造与迁移说明

原基线：f59ab2270fab3208ae5748124099a6cce45afe34。

## 行为变化

- 读取资料不自动激活规则；用户采纳后固定 commit、范围与例外。
- 统一外部动作授权，删除模板中测试后自动推送的冲突要求。
- 用实际技术状态、用户验收和发布状态代替固定进度比例；模板默认 not_run。
- 原始业务项目快照移出默认分发内容，历史不重写；合成案例不携带历史授权。
- PRD/测试/交接以 ID 关联，减少重复状态；文档按任务风险裁剪。
- 保留业务项目既有版本规范，不强制切换 X.Y.ZZ；规则版本使用 commit。
- UI 改为 8 项可追溯规则，保留产品差异、可访问性和受控例外，父级状态不得伪造子项验收。

## 新增能力

- 确定性聚合生成、统一薄入口和 UI 模板一致性检查。
- 规则编号/链接/默认状态/已知危险文字静态检查。
- UI 材料覆盖、版本、证据摘要、路径与例外期限检查。
- 设计变量定义与计算值采样比较，并检查声明组件/主题是否采样。
- 18 个真实 Agent 对抗场景定义与独立评测流程；当前未接入实际模型运行器。
- 本地负向回归与 GitHub Actions 工作流；GitCode 平台门禁仍需实际接入。

## 下游迁移

先审阅新母本和授权差异，再更新固定版本。将旧看板的成功状态核实后转换，缺证据保持未验证，不批量迁移成 passed。UI 项目建立组件与变量清单，填默认报告，采集真实运行证据。更新截图基线需审阅；不因引入新模板删除已有用户规范或业务设计。

优先在一个小项目试用，验证授权、交接、规则生成及 UI 报告流程后再扩大使用。执行层权限、可信 CI、凭据轮换、真实模型/平台验证不能由本次文档与本地测试替代。
